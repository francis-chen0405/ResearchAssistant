## Implementation and safety

- Neutral `contracts.source_leads` contracts and `storage.source_leads` own a
  detached projection from one validated read-only snapshot. Storage reads neither
  research nor agent execution. `GET /api/research/{run_id}/source-leads` is guarded
  by the existing host/origin/session boundary and works without a final artifact.
- Pagination is offset 0–6,000 / limit 1–100; the renderer requests 50. Inspection
  bounds its inventory at 12,000 artifacts / 128 MiB and rejects overflow before
  payload materialization. Artifact checksums, typed stage/key/run ownership,
  cluster/ranking membership, parser/physical lineage, capture journal pairs and
  source snapshot hashes are validated. Missing files are never created/migrated.
- The UI loads leads independently, aborts stale reads, bounds/guards pagination,
  shows reasons/readability, and collapses metadata/history. HTTP(S) links exclude
  embedded credentials. Search direction is explicitly provenance only. Recorded
  confidence concerns the disposition, not source truth or human usefulness.
- Only the capture journal contracts were extracted for this reader. Historical
  acquisition-agent exports are identical objects with their original public class
  identity. Probe v1–v4 dispatch and serialization remain unchanged.
- Compiler/discovery identities stay v3 and fresh acquisition stays Probe v4.
  The view names its projection identity; changed backend source identity still
  requires a fresh run under the exact compatibility gate. The frozen Prompt 14
  allowance/inputs/receipt are unchanged and reject this current runtime before
  credential reads. No approval is converted to cover changed factors.
- Neutral conformance fixtures exercise all five existing metadata adapters with
  offline mock transports: common result types, URL filtering, retained bounds,
  page/raw-rank provenance, serialization and typed malformed/rate-limit errors.
  No provider-specific type enters storage/contracts/UI and no new provider is added.
