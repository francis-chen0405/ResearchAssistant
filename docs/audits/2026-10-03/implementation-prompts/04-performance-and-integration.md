## 2. Coherent requests and explicit reader/writer behavior: I4

Make each public multi-query history, status, inspection, trail, browser, and export request observe one coherent committed database state. A single connection by itself is insufficient because consecutive selects can see different commits. Establish an explicit, short-lived read snapshot at the appropriate public boundary; preserve borrowed-connection ownership, close cursors deterministically, and ensure exceptions release locally owned transactions and connections. Reuse an existing caller-owned transaction safely rather than issuing a nested BEGIN or committing/rolling back somebody else's work; test nested/borrowed cases. Do not keep database transactions open across provider/network work, user interaction, slow export rendering, or inactive UI intervals. Choose and document a reader/writer policy using contention tests and measurements.
