## Phase-specific task

Prerequisite: verify Phases 1–2 in actual code. Replace the five-result-only bottleneck with bounded deeper metadata discovery and meaningful ranking before expensive acquisition. Deliver real execution, persistence, and tests; increasing a `limit` constant alone is insufficient.

## 1. Implement depth and pagination per provider

Use the frozen discovery policy's requested depth, effective provider limit, page cap, round/run retained-record caps, and remaining provider budget in both initial and adaptive execution. Implement provider-specific result count and pagination where officially supported. SERP currently uses page 1; OpenAlex/arXiv/PubMed/Exa have their own paging/count semantics. Verify each endpoint rather than pretending every engine implements the same cursor or result depth. If a provider can return only a smaller number safely, persist requested/effective depth and the limiting reason.

Reserve/account each physical page or metadata request separately, including failures, retryable statuses, malformed pages, and unknown completions. A logical operation can span several bounded pages; a page is not a free call. Honor rate limits, deadlines, cancellation boundaries, response-size bounds, cursor validation and same-origin endpoint restrictions. Detect repeated pages/cursors, empty/no-new-result pages, inconsistent ranks, duplicate records, and early stop. Persist successful pages before continuing and preserve partial results if a later page fails. Checkpoints must support safe replay without repeating known-completed transport or discarding unknown exposure.

Keep raw provider rank/page provenance and bounded metadata even when a record is never selected. Normalize stable work identity and retain conflicts explicitly. Preserve conservative DOI/URL/title grouping and source-family identity; do not declare independent studies from distinct domains. Do not add arbitrary full-text downloads to metadata adapters or bypass independent acquisition.

## 2. Rank the wider pool fairly

Implement versioned deterministic metadata ranking, with configurable bounded signals whose rationale is persisted: directness to the claim's asserted components; plausible study/method/source type; needed gap coverage; trusted identity/metadata completeness; novelty against already discovered work; and useful provider/source-type diversity. Citation count, publication age, or a domain suffix alone must not determine quality. Missing metadata is unknown, not evidence of poor quality. Keep search-direction provenance separate from evidence relationship.

Do not compare raw relevance scores across providers as though their scales match. Use documented within-provider normalization or independent common features. Use stable tie-breaks, deterministic per-lane allocation, conservative duplicate penalties, and transparent metadata-rank provenance. Preserve enough breadth that a paper ranked below five by its engine can reach the acquisition shortlist. Maintain recall for potentially relevant null/contradictory findings and scarce minority research lanes.

Bound the Scout input by policy and protected model budget. Preserve all retained candidates with explicit `not_scouted`/cap/budget dispositions; never fabricate a Scout rejection for an item the model did not see. Every item actually sent to Scout requires the existing complete decision mapping. Update Scout prompt/input version if ranking context is added, without letting Scout admit facts. More metadata must not create an unbounded number of Scout/model calls or overfill a single prompt. Conserve downstream selection/extraction/Analyst capacity.

## 3. Integrate ranking with existing acquisition and final selection

Build the acquisition candidate ordering from the new rank plus Scout decisions, respecting hard round limits and disabled providers/directions. Sources not acquired retain an explicit disposition. Preserve independent acquisition, validated URLs/redirects, existing media handling, snapshot immutability/3,000-word cap, exact extraction, deep-analysis limits, and current error-shell rejection. This phase does not add OCR, unrestricted crawling, paywall bypass, or automatic full-text-recovery loops.

Keep discovery rank and final Source Selection recommendation distinct: the first chooses likely useful sources to acquire, the latter assesses the usable survivor pool. Connect Phase 4's preview-aware selection through a typed extension point with a working deterministic fallback until that phase is present. Do not ship a placeholder that fails on ordinary runs. Audit counting must distinguish raw hits, deduplicated works, scouted candidates, acquisition-shortlisted clusters, fetched documents, usable survivors, and evidence admission. Historical counts retain their original meaning.
