## 2. Build a documented capability-specific compiler

Read current official primary documentation while implementing; record URLs and verification dates. Relevant starting points are:

- OpenAlex: https://help.openalex.org/api/searching/ and https://help.openalex.org/api/semantic-search/
- arXiv: https://info.arxiv.org/help/api/user-manual.html
- PubMed/E-utilities: https://www.ncbi.nlm.nih.gov/books/NBK25499/ and official NCBI alternatives if that page is unavailable.
- Exa: https://exa.ai/docs/reference/search
- The existing SERP provider and any enabled Serper adapter's actual official API documentation/configuration.

For OpenAlex, implement supported phrase/Boolean concept searches and a genuine semantic request mode. The existing adapter's `request.semantic` switch is currently unused by ordinary orchestration; connect it through the new frozen policy. Respect documented field/mode/filter restrictions. Semantic, lexical, filtered lookup, and any optional upstream rerank may have different prices/limits. Do not silently enable paid upstream reranking or apply lexical pricing to other modes. Provide a budget-safe lexical fallback only as a distinct recorded/reserved attempt when policy allows.

For arXiv, compile explicit fielded/Boolean expressions with correct escaping, rather than prepending `all:` to an arbitrary natural-language sentence. For PubMed, produce supported fielded/Boolean term combinations without inventing MeSH mappings or invalid tags. For Exa, provide concise natural-language intent and only supported structured parameters; do not force a scholarly Boolean language into semantic web search. For SERP-style search, support verified search operators/phrases and avoid unsupported API parameters. Existing provider choices stay user-controlled: topic suitability informs wording and ranking but never silently enables a disabled provider or drops an enabled lane.

Keep aliases bounded and justified, e.g. ALPR/LPR/ANPR and full phrases where appropriate. Do not add an exhaustive acronym alone if it causes broad ambiguity. Avoid biased exclusions such as removing null results or evidence contradicting a support-directed query. Date, language, publication type, and authority restrictions require explicit documented policy; do not arbitrarily filter away older foundational studies.
